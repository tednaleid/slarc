# slarc rm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Mark a task's heading `[done]` and tick its steps in the same commit that finishes it.

**Goal:** Add `slarc rm <selector>`, which stops tracking items and deletes what no remaining tracked item needs. Make pull skip Slack-archived conversations after one final refresh, warn only once about not-visible items, and stop retrying outside-site images after 3 failures, with `--full` retrying them.

**Architecture:** As today:
- **Domain:** tracking types gain new statuses and a field.
- **Service:** a new `service/remove.py` plans and applies a removal through ports.
- **Adapters:** the JSONL and blob store adapters gain the deleting methods. These are the only code that rewrites or deletes archive files.
- **CLI:** `slarc rm` prompts with the plan before applying it.

**Tech Stack:** Python 3.14, uv, Typer, msgspec, pytest.

**Spec:** `docs/specs/2026-10-19-rm-design.md` (binding for this plan), plus `docs/specs/detailed-requirements.md`, `docs/architecture.md` and `GLOSSARY.md`.

## Global Constraints

- **Code style:**
  - Every code file starts with two `# ABOUTME: ` lines.
  - `just check` passes before every commit. Use `just` recipes, never bare tools.
  - Test first: watch each new test fail before making it pass.
- **Layering:** domain and service modules never import `slack_sdk`, `httpx`, `duckdb` or `keyring`, and never touch the filesystem or environment. File rewrites and deletions happen only in `adapters/jsonl_store.py` and `adapters/blob_store.py`.
- **Slack:** `slarc rm` never calls Slack. No task makes live Slack calls.
- **Secrets and privacy:** never print, log or commit a token, cookie or keychain secret. Use only fixture names (`naleidworkspace`, `acme`, `other`, `#all-naleid`) in code, tests and docs. Never read the repo's `archives/` directory.
- **Text:** user-facing messages are one or two plain sentences with no traceback, using glossary terms. No emoji or em dashes anywhere. Comments are evergreen.
- **Docs:** when a task changes behavior the spec or `docs/architecture.md` describes, update that text in the same commit.

## Review Focus

1. `rm` of a thread link while its conversation is tracked deletes no message line, and says it kept them. Test: Task 6 `test_rm_thread_inside_tracked_conversation_keeps_its_messages`.
2. A pull after `rm` must not re-download files of the messages it deleted. Test: Task 6 `test_pull_after_rm_does_not_requeue_removed_downloads`.
3. `rm` killed after its run line but before the sweep: running the same `rm` again finishes the sweep. Test: Task 6 `test_rm_rerun_after_interrupted_sweep_finishes_it`.
4. A blob also referenced by another workspace's directory line survives `rm` of the first workspace. Test: Task 6 `test_rm_keeps_blob_another_workspace_references`.
5. A conversation archived since the last pull gets one more full refresh, so messages posted just before archiving are stored. Test: Task 2 `test_newly_archived_conversation_is_refreshed_once_then_skipped`.

### Task 5: Storage ports for removal

**Files:**
- Modify: `src/slarc/ports.py`, `src/slarc/adapters/jsonl_store.py`, `src/slarc/adapters/blob_store.py`, `tests/fakes.py`
- Test: `tests/contract/test_archive_store.py`, `tests/contract/test_blob_store.py`

**Interfaces:**
- **Produces, on `ArchiveStore`:**
  - `channels(team: str) -> list[str]`: the channel ids that have stored message lines.
  - `message_lines(team: str, channel: str) -> Iterator[Envelope]`: every message and deleted line, every version, in file order.
  - `drop_messages(team: str, channel: str, stamps: set[str]) -> int`:
    - removes every line whose `meta.ts` is in `stamps` and returns how many lines it removed;
    - deletes month files left empty, and the channel directory when it is empty;
    - invalidates the `stored_messages` cache for that channel.
  - `drop_directory_lines(team: str, kind: Kind, ids: set[str]) -> int`: removes every line of that kind whose `meta.id` is in `ids`. It is used for `file` and `image`.
  - `drop_workspace(team: str) -> None`: deletes `raw/<team>/` and `directory/<team>/`.
  - `blob_references() -> list[tuple[str, Kind, str, str]]`: `(team, kind, id, blob)` for every directory line in every workspace that has `meta.blob`.
- **Produces, on `BlobStore`:**
  - `ids() -> Iterator[str]`: every stored blob's sha256.
  - `delete(sha256: str) -> None`.
- **Rewriting rule in `jsonl_store.py`:**
  1. Close and forget any open append handle for the file.
  2. Write the kept lines to a temp file in the same directory, `flush`, then `os.fsync`.
  3. `os.replace` it over the original.
  4. A failure raises `ArchiveWriteFailed` and leaves the original intact.
  5. Lines that do not decode are kept as they are.

### Task 6: The removal use case

**Files:**
- Create: `src/slarc/service/remove.py`
- Modify: `docs/architecture.md` (service module list)
- Test: `tests/service/test_remove.py` (new; build a harness from the pull harness or the fakes, so tests can pull real fixtures and then remove)

**Interfaces:**
- **Consumes:**
  - Task 1's `removed_items`.
  - Task 5's port methods.
  - `archived_conversation` and `only_workspace` (`service/selectors.py`) and `workspace_domains` (`service/listing.py`) to resolve selectors without Slack, the same way `service/export.py` does.
  - `image_urls` (`service/downloads.py`) and `directory_image_url` (`domain/directory.py`) for references.
  - `outstanding_downloads` (`service/downloads.py`).
- **Produces:**
  - `@dataclass(frozen=True) class Removal` with these fields:
    - `items: list[TrackedItem]`: tracked items the selectors name, about to be removed;
    - `already_removed: list[TrackedItem]`;
    - `teams: list[str]`: affected workspaces;
    - `wiped_teams: list[str]`: workspaces with nothing left tracked;
    - `lines: int`, `files: int`, `images: int`, `blobs: int`: what the sweep will delete;
    - `kept_messages: int`: messages in the named items' coverage that other tracked items still cover.
    - It also has a `nothing_to_do` property.
  - `plan_removal(selectors: list[Selector], channel_mode: bool, archive: ArchiveStore, blobs: BlobStore, index: QueryIndex) -> Removal`.
    - It raises `SlarcError(f"Nothing tracked matches {text}.")` for a selector that names neither a tracked nor a removed item. `text` is the selector as typed; carry it on the selector or pass the texts alongside.
  - `apply_removal(removal: Removal, uow: UnitOfWork) -> None`:
    1. Records each named item with `status="removed"` in `uow.run.tracked`.
    2. Records a `DownloadState(status="removed")` for each download target the sweep will orphan.
    3. Sets `uow.run.counts` (`lines_deleted`, `files_deleted`, `images_deleted`, `blobs_deleted`).
    4. Leaves the run line to the unit of work.
  - `sweep(teams: list[str], archive: ArchiveStore, blobs: BlobStore) -> None`: the idempotent deletion, computed from the current tracked items. The CLI runs it after the unit of work has exited and written the run line.
  - **Shared computation:** `plan_removal` and `sweep` share one private function that computes what to delete when given items to exclude. This keeps the prompt's counts equal to what the sweep deletes.
- **Coverage, references and the sweep:** follow the design doc exactly. The design's "Coverage", "Files and images" and "Order of writes and recovery" sections are the requirements; do not re-derive them.

### Task 7: The `slarc rm` command

**Files:**
- Modify: `src/slarc/cli.py`, `docs/specs/detailed-requirements.md` (commands section), `README.md` if it lists commands
- Test: `tests/test_cli_rm.py` (new; reuse the pull CLI fixture pattern from `tests/test_cli_pull.py`)

**Interfaces:**
- **Consumes:** `plan_removal`, `apply_removal`, `sweep` (Task 6).
- **Produces:** `slarc rm SELECTORS... [--channel] [--yes] [--root DIR]`.
  - **Help text:** the same selector help as `pull` and `export`, plus "Do not run while a pull is running on the same archive."
  - **Order of operations:**
    1. Plan the removal.
    2. If it has `nothing_to_do`, print `Nothing to remove.` and exit 0.
    3. Otherwise prompt, unless `--yes` was given.
    4. On yes, apply the removal inside `UnitOfWork(..., "rm", args, ...)`.
    5. After the unit of work exits, run the sweep.
    6. Print the result.
  - **Prompt and output text:**
    - **Prompt, with something to delete:** `f"Stop tracking {N item(s)} and delete {L line(s)}, {F file(s)} and {I image(s)}?"`, with the parts that are 0 dropped. On the next line: `Messages deleted from Slack since they were pulled cannot be pulled again.`
    - **Prompt, with nothing to delete:** `f"Stop tracking {N item(s)}?"`.
    - **Default answer:** No (`typer.confirm(..., default=False)`).
    - **Declining or an aborted prompt:** prints `Nothing removed.` and exits 1.
    - **Result:** `f"Stopped tracking {N item(s)}; deleted {L line(s)}, {F file(s)} and {I image(s)}."`, with zero parts dropped. Append `f" Kept {K message(s)} that other tracked items cover."` when `kept_messages` is nonzero.
    - **Cleanup-only run** (all named items already removed): `f"Cleaned up {L line(s)}, ..."`.
  - **Interrupts:** Ctrl-C prints the interrupt message and exits 130, as `pull` does.
